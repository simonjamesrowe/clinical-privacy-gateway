Design system

The visual reference for the patient-centred interface. Tokens come from src/styles/tokens.css and components from src/styles/components.css, so this page shows exactly what the app uses. Rules, decisions and the delivery plan live in docs/design-system.md. All content is synthetic.

  • The patient is the centreOpen a patient, then work in their Details, Notes and Redactions tabs.
  • One level of navigationHeader destinations, one row of patient tabs, nothing deeper.
  • No modals or overlaysForms are pages, and confirmations and edits expand inline.
  • Two scopes, one componentNotes and redactions use the same table for all patients and for one patient.
  • One primary action per viewOnly one teal button is on screen at a time.
  • State is text as well as colourYellow means pending and green means decided, always with a label.
  • Local, visibly“On this Mac” stays in the header on every workspace screen.

Space and shape

A 4 px spacing base, one radius, and two control heights. There are no shadows except on the anchored selection menu.

Buttons

Intents and sizes

  • Primary appears once per view. Secondary is the default.
  • Quiet is for low-emphasis actions such as Cancel and Edit.
  • Danger-quiet starts a deletion. Danger confirms it inline.
  • Compact is for table rows.
  • Labels name the outcome, for example Save changes or Delete note.

Fields and search

Field

  • The label is above the input. A hint or error goes below.
  • Errors set aria-invalid and are referenced by aria-describedby. They never contain clinical text.

Search

  • The input is joined to a secondary Search button with a magnifying-glass icon. Enter or the button runs the search.
  • The status line gives the match count and the query, with Clear search.

Tables

Data table with inline confirmation

  • The whole row opens the item. Actions are right-aligned and compact.
  • Delete expands a confirmation in place with the question, the consequence, Cancel and a danger button. Focus moves to Cancel.
  • The patient scope drops the Patient column. Nothing else changes.

Feedback

Badges, notices and empty state

  • Badges always carry text. Pending and decided match the review states.
  • Notices explain scope or report a page-level error with role="alert".
  • An empty state gives one sentence of direction and the action that fills it.

Document notes

Import and original previews

Original-document action

  • Show the file format and a document icon in the Original column; keep the note title as the review action.
  • The accessible label and tooltip name the original format. The action must not trigger the row opener.
  • Keep filenames out of search excerpts. Show them inside the original preview and import toolbar.
  • Use the document toolbar, content and paragraph components with shared tokens. Render text as text nodes and PDF pages as inert images.
  • Import tabs share the keyboard tab pattern. Warnings require an explicit check before analysis.
